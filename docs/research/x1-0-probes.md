# X1-0 — `claude -p` against a loopback Anthropic stub

**Date:** 2026-11-27. **Binary:** `/Users/chandra/.local/bin/claude` → `2.1.325 (Claude Code)`, Node `v26.12.1`, Anthropic SDK (Stainless) `0.128.0`. **Host:** macOS, arm64.
**Tools (Python 3 stdlib, run with `python3 -I`):** `docs/research/probes/x1-0/stub_anthropic.py` (the stub), `docs/research/probes/x1-0/deny_proxy.py` (the deny-all proxy), `docs/research/probes/x1-0/run_probes.sh` (the legs). **Raw logs:** `docs/research/probes/x1-0/logs/<leg>/{cmd.txt,status.txt,stdout.jsonl,stderr.txt,stub.log,deny.log}`.

**Method.** Every leg ran `timeout 120 env -i <minimal env> claude -p "Reply with exactly: ok" --output-format stream-json --verbose [extra args]` in a fresh temporary cwd holding one file (`hello.txt`), with `HTTPS_PROXY=HTTP_PROXY=https_proxy=http_proxy=http://127.0.0.1:<deny port>`, `NO_PROXY=no_proxy=127.0.0.1,localhost`, `ANTHROPIC_BASE_URL` pointing at the stub, and `ANTHROPIC_API_KEY` = 64 lowercase hex characters generated at run time (never written to any log; the stub logs credential headers as `<redacted len=N>` only). "Fresh" legs set `CLAUDE_CONFIG_DIR` to an empty temporary directory; the "default" legs (h) left it unset, so the owner's logged-in configuration was used — those legs only *ran* the unmodified binary; no credential or configuration file was read, copied or printed. The deny proxy answers 403 to everything and never connects; `exit 124` means `timeout 120` killed `claude`. The stub serves `POST /v1/messages` (SSE in the real event order: `message_start → content_block_start → content_block_delta* → content_block_stop → message_delta(stop_reason, usage) → message_stop`; a JSON form when `stream` is false) and `POST /v1/messages/count_tokens`.

## What every request looked like (fresh config, API-key mode)

- **Target:** `POST <base>/v1/messages?beta=true` — the only query string seen, on every request; with a base URL path prefix the path is `<prefix>/v1/messages?beta=true`. No other endpoint (no `count_tokens`, no `/v1/models`).
- **Request headers (names, in order):** `Accept: application/json`, `Content-Type: application/json`, `User-Agent: claude-cli/2.1.325 (external, sdk-cli)`, `X-Claude-Code-Session-Id: <uuid>`, `X-Stainless-Arch: arm64`, `X-Stainless-Lang: js`, `X-Stainless-OS: MacOS`, `X-Stainless-Package-Version: 0.128.0`, `X-Stainless-Retry-Count: <n>`, `X-Stainless-Runtime: node`, `X-Stainless-Runtime-Version: v26.12.1`, `X-Stainless-Timeout: 600`, `anthropic-beta: claude-code-20250219,interleaved-thinking-2025-05-14,context-management-2025-06-27,per-turn-control-2026-07-01,mid-conversation-tool-changes-2026-07-01,thinking-token-count-2026-05-13,advanced-tool-use-2025-11-20,effort-2025-11-24,thinking-display-updates-2026-08-18`, `anthropic-dangerous-direct-browser-access: true`, `anthropic-version: 2023-06-01`, `x-api-key: <64>`, `x-app: cli`, `Connection: keep-alive`, `Host: 127.0.0.1:<port>`, `Accept-Encoding: gzip, deflate, br, zstd`, `Content-Length: ~46–50 KB`. HTTP/1.1.
- **Body keys:** `context_management`, `max_tokens` (128000 for `claude-opus-5-5`; 32000 for an unknown model name), `messages`, `metadata` (`user_id` = a JSON string `{"device_id": <64 hex>, "account_uuid": "" | <owner's uuid in OAuth mode>, "session_id": <uuid>}`), `model`, `output_config`, `stream: true`, `system` (3 blocks, ~6 KB, with `cache_control`), `thinking` (`type`, `display`), `tools` (12: `Agent, Bash, Edit, ListAgents, Read, ReportFindings, ScheduleWakeup, Skill, ToolSearch, Workflow, DeferredToolPlaceholder, Write`); the default-config legs add `safeguards`. **`messages` contains a `role: "system"` message** (one ~9.9 KB text block after the first user message; a plain string on `--resume`) besides the top-level `system` — a gateway that re-encodes for an OpenAI-compatible provider must accept and map it.
- **Response claude accepted:** the canonical order above, `usage` in `message_start` and `message_delta`; it also accepted a stream with no `message_stop` and one with a leading `[DONE]`.

## The `api.anthropic.com` CONNECTs

Every leg without `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` — including the fresh-config legs, where no login exists — made 3 `CONNECT api.anthropic.com:443` attempts at start-up and more during retries (17 in a 429 or 401 leg: two at start, then bursts with their own backoff). They were all refused by the deny proxy and the turns still completed through the stub, so they are **not** the Messages call falling back to Anthropic: they are claude's non-essential traffic (feature flags / telemetry; TLS, so the path is unknown). With the switch set (leg b) there were **zero**. The default-config legs added one `api.github.com:443` and one `http-intake.logs.us5.datadoghq.com:443` from the owner's plugins and `SessionStart` hooks, which ran inside the turn.

## Stop-rule verdict (brief Step 2)

**Not blocked.** With the base URL, the 64-hex turn token and the deny proxy set — and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` — a `claude` turn under the owner's logged-in default configuration made **no connection to any host but the stub**, even through nine 401 and nine 429 refusals (h1b, h3b, h4b: deny log empty; every request carried `x-api-key` and no `authorization`). Without the switch, the CONNECTs to `api.anthropic.com:443` are present but identical in the fresh-config legs (no login to use) and were all refused; the Messages call never left the stub (h3, h4). So the gateway turn is fail-closed as the plan needs.

Two things leg (h) **did** show, which the plan must absorb (controller ruling 1: record, do not stop):

1. **With `ANTHROPIC_BASE_URL` set and no `ANTHROPIC_API_KEY`, claude sends the owner's OAuth bearer token to the custom base URL** (h2, h2b: `Authorization: <115 chars>`, `apiKeySource: "none"`, the owner's `account_uuid` in `metadata.user_id`). A gateway turn must therefore never be launched without its turn token, and a turn that has the base URL but lost its token must fail at compile time.
2. **Under the default config dir the owner's hooks and plugins run inside the turn** (two `SessionStart` hooks, a Datadog log sink, `api.github.com`) and the request body gains `safeguards`. Gateway turns use an **isolated per-turn `CLAUDE_CONFIG_DIR`** — an empty scratch directory under the agent home, never a copy of the owner's (controller ruling 1). With an empty config dir and the token, `apiKeySource` is `ANTHROPIC_API_KEY`, no hook runs, and `--resume` still works (leg i, same config dir across runs), so the per-agent dir must persist across turns of one agent for resume to keep working.

No credential or configuration file was read, copied or opened by the probe; the default-config legs only ran the unmodified binary.
