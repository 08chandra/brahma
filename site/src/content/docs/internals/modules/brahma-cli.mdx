## Purpose

The command-line executable over the same library. `Brahma` in `Brahma.swift` is the root `AsyncParsableCommand`; its `subcommands` list names every command group, one Swift file each. Owner commands open the store, do their work and exit. `brahma run` builds an `Orchestrator` and runs it in the terminal under the lock the app uses; `brahma mcp` runs the company MCP server for one agent over stdio; `brahma hook` is the tool hooks the `claude` process runs inside agent turns. `CLISupport.swift` holds what every command shares: `openStore()`, the secret vault, `safe()` and `fail()`. The [CLI reference](/docs/cli/) is generated from `brahma --help`.

## Key types

This target has no public symbols, so there is no API reference for it. The types and functions below are internal.

- `Brahma` — the root command; its `subcommands` array is the list of command groups.
- `openStore()` — resolves the data home, refuses a bad secret-store choice, opens the `Store`, validates and locks down the data home, and arms the lazy secrets loader.
- `cliSecretVault(interactive:)` — the process's vault; interactive only for explicit owner actions.
- `safe()` and `fail()` — agent-controlled text never reaches the terminal raw; errors go to stderr as `brahma: <message>` with exit code `1`.
- `Run` — `brahma run`: the orchestrator in the foreground until Ctrl-C.
- `MCP` — `brahma mcp`: the company tools server over stdio.

## How it connects

- **Calls BrahmaCore.** `42` of the `43` files import it; `Brahma.swift` is the one that does not. `openStore()` builds the `Store` with `PackCatalog.loadOrBuiltin` and runs `DataHomeGuard`; `Run` builds an `Orchestrator`; `MCP` builds an `MCPServer` over `CompanyTools`; `Doctor` runs `Doctor.run`; `hook pre-tool` and `hook post-tool` call `PreToolHook.run` and `PostToolHook.handle`.
- **Calls BrahmaKeychain.** `6` files import it. `openStore()` refuses a bad store choice first; `cliSecretVault` and `ownerKeyStore(for:)` resolve the vault and the owner-key store; `brahma mcp` resolves its vault non-interactively.
- **Started by the engine.** `brahma run` passes its own executable as the MCP executable for each turn's `brahma mcp`; the app looks for the same binary at `Contents/Helpers/brahma` inside its bundle. `brahma hook` is run by the `claude` process, from the `hooks` entries in the settings file the engine compiles for each turn.
- **Called by nothing in the package.** It is an executable target; `Package.swift` lists its dependencies as `BrahmaCore`, `BrahmaKeychain` and `ArgumentParser`.
