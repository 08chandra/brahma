One page per Swift target and per `BrahmaCore` area. The [architecture](/internals/architecture/) page shows how they fit together; the [API reference](/api/) lists the public types.

## Swift targets

| Target | What it is | Page |
| --- | --- | --- |
| `BrahmaCore` | The library every other target links: engine, work system, store, sandbox. Split into 29 areas. | [BrahmaCore](/internals/modules/brahmacore/) |
| `BrahmaAppModel` | The Mac app's state, with no AppKit or SwiftUI import. | [BrahmaAppModel](/internals/modules/brahmaappmodel/) |
| `BrahmaApp` | The SwiftUI views and the menu bar extra. | [BrahmaApp](/internals/modules/brahmaapp/) |
| `BrahmaMapKit` | SpriteKit rendering of the live agent map. | [BrahmaMapKit](/internals/modules/brahmamapkit/) |
| `BrahmaKeychain` | The macOS Keychain behind two `BrahmaCore` protocols. | [BrahmaKeychain](/internals/modules/brahmakeychain/) |
| `CSandboxCheck` | Three C functions over `sandbox_check`. | [CSandboxCheck](/internals/modules/csandboxcheck/) |
| `brahma` | The command-line executable over the same library. | [brahma](/internals/modules/brahma-cli/) |
